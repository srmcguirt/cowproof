- **Dependency prefetch (D6, D11, D14, F-1): done for Cargo (2026-10-10, audit blocker 5).**
  - **Flow.** Before verify runs, `cowproof run` rebuilds the tree (base commit, `base.patch`, launch baseline, `lane.patch`), computes `dependency_cache_key` on it and looks in `<cache root>/deps/<key>/`. The cache root is `~/.cache/cowproof`, or `$COWPROOF_CACHE_ROOT` (the override tests use). A miss runs `cargo fetch --locked` in a private work directory under the cache root and renames it into place, so no concurrent lane sees half an entry; a lane that loses the rename race reports `hit`. The capsule records the key and the outcome (`hit`, `fetched`, `failed`) in `capsule.json`, which the seal covers. `cowproof verify` does the same from the capsule's key (it fetches when its own cache root lacks the entry) and refuses a rebuilt tree whose key differs.
  - **The fetch sandbox** (`SandboxPolicy::dependency_fetch`) writes only its own work directory and reads the rebuilt tree, the toolchain and the one `cargo` executable. Its environment is `PATH`, `CARGO_HOME`, `RUSTUP_HOME` and `HOME`; it holds no key, cannot see the lane's control directory, the other lanes or the real home, and `cargo fetch` runs no `build.rs` or procedural macro. **Its network is the one knob: `COWPROOF_FETCH_NETWORK`, `open` by default (full outbound network) or `none`.** The default is `open` because the registry-only egress filter (`NetworkMode::RegistryReadOnly` through the proxy) does not exist, and a no-network default would fail every real project. The tests use `none` with a registry on disk.
