  - **The escalation resume loop and the `Stop`, `Redirect` and `Reassign` verdicts: done (D9, D22, D25).** After each builder exit the runner asks the queue for the lane's blocking escalations that have not reached the builder (`Queue::pending_blocking`) and, if one is parked, waits for the director's ruling with no timeout but the queue's own park limit (`Queue::expire_parked` ends the lane as `escalation-limit`; `Queue::rule` only checks the limit when a ruling arrives, so a silent director would have parked the lane forever). The director socket's channel is only a wake-up; the queue is read again on every wake. `answer` relaunches `claude --resume <newest session id from the stream>` with `Director ruling on <id>:` and the answer in a fence; if the session is gone the queue's own fallback runs (`Queue::redeliver`: `resume-fallback`, counted against the limit) and the runner launches a fresh session on the packet plus the queue's carry-over summary. `redirect` reads, checks the id and lints the new packet, then a fresh session whose prompt is its body. `reassign` calls `Queue::reassign` and starts a fresh session on the next model (haiku, sonnet, opus) or the named one, with the question and what was tried. `stop` sets the lane `stopped`. Stop, Redirect and Reassign tell the queue only that the ruling was delivered; they never go through the fallback. `settings.json`, `mcp.json` and `system-prompt.md` are rewritten before every launch. `run.json` has a `segments` array: model, start (`fresh`, `resumed`, `fallback`), session id, resumed session, the escalation that started it and the one that ended it, exit status, turns. Tests: `crates/cowproof-cli/tests/run.rs` plays the director with the real `cowproof rule`. Open:
    - **Session gone is detected conservatively, not by message.** A resumed launch counts as gone only if it exited with a non-zero code, wrote no stdout line, metered no turn and took under 60 seconds (`resume_session_gone`). `claude` has no documented signal; the real failure text has not been checked against this rule. A false positive costs one fresh session and one escalation; a false negative leaves the lane `failed` with the resume's stderr in `control/builder.stderr`.
    - **The runner ends the builder's session on a parked blocking ask, and on a forced escalation: done (D9).** `cowproof run` creates a session-end channel before the tools server and the builder start; `tools::serve_signalling` sends on it when a blocking `ask` parks the lane, when `run_check` forces an escalation, or when a call ends the lane at the escalation limit, and the escalate-early observer (below) sends on it too. `Launcher::launch` races the stream pump, the child wait and that signal in one `select!` (the pump is never awaited to EOF first). On the signal it waits 2 s (the tool reply lands, `claude` flushes its session; a builder that exits by itself in that time is not touched), sends SIGTERM to the builder's process group, waits up to 10 s for the leader, then SIGKILLs the group whether or not the leader has exited. When the leader exits for any reason the group is SIGKILLed too, so no background child outlives a launch or holds the stream open, and the pump gets 5 s more to reach EOF before it is abandoned. Only the builder's spawn is its own process group (`process_group(0)`); `run_check` and the git steps keep the runner's group, so a terminal Ctrl-C still reaches them. The group kill is `cowproof_prove::runner::{kill_process_group, terminate_process_group}`, the verifier's own code made public, not a copy. Segments in `run.json` carry `sessionEnd` (`parked`, `forced`, `escalation-limit` or null), `killedByRunner` and `status: "ended-by-runner"`. Open:
      - **Ctrl-C on `cowproof run` now leaves the builder running.** The builder is no longer in the terminal's foreground group, and the default SIGINT ends the runner without unwinding, so the `GroupGuard` safety net does not run. Install a SIGINT/SIGTERM handler that ends the builder's group and then exits.
      - **A signalled group is addressed by its leader's pid after the leader is reaped.** Same pattern as the verifier's timeout kill; a recycled pid inside the 5 s window is the (negligible) risk.
      - **The pid-based check of the kill test runs on macOS only.** bwrap runs with `--unshare-pid`, so a pid recorded inside the sandbox means nothing outside it; on Linux the test proves the kill by effect (a background child's marker file never appears).
    - **Delivery is recorded after the launch, not inside it.** `Delivery::deliver` is synchronous and runs with the queue locked, which the lane's own tool server needs to answer the builder, so the runner launches first and reports what happened through `Queue::redeliver`. A crash between the launch and the record leaves the ruling recorded and undelivered.
    - **A stopped or escalation-limit lane is not proved** and `cowproof run` exits 1 for both; `run.json` `status` says which. The design keeps their work for inspection; the exit-code table in `run --help` (main.rs) has no code for them. The `stopped` state lives in memory only, like every state but `escalation-limit`.
    - **A redirect changes the prompt, not the proof.** The proof still uses the original packet's header (checks, owns); gates "use the final version" of the packet, and `packets/` is not written (see above).
    - **Several blocking asks parked at once** are ruled one at a time, oldest ruled first; each later one is waited for after the next launch ends, even if the resumed builder has moved on.
