## Blockers for step 6 (prove the slice)

1. **The builder preamble promises `pk-read`, `sym` and `outline`**, which are not served, installed or granted inside the sandbox. Drop them until they are served.
2. **A parked blocking ask does not end the builder's session.** `pump_stream` runs to EOF before anything listens for the parked signal; a builder that keeps running is never stopped.
3. **Escalate-early is not live.** `Queue::record_cost` and `record_turn` have no caller in `cowproof run`; the 40 percent cost share and the turn budget never fire. After a trigger fires, `record_check` and `record_turn` fire again on every later failure or turn, which burns the escalation limit. A forced escalation never ends the session.
4. **No `cowproof verify <capsule>` command.** Success criterion 1 replays a capsule on a second machine.
5. **No dependency prefetch (D6, D11, D14).** A check that needs crates fails offline in verify and is judged `refuted`; F-1 says it is infrastructure.
6. **Held-out checks are not wired into `cowproof run`** (`heldout_path: None`, `require_heldout: false`). The adversarial packet in step 6 needs them.
7. **No live run against a real `claude`.** Every test uses a fake; the R15 proof, the permissions block, the https upstream and the header allowlist are unverified. Needs the founder's approval for API spend.
   - **Live smoke run (2026-10-10):** Real `claude` 2.1.295 builder launched by `cowproof run` reported these built-in tools available: `Task`, `Bash`, `CronCreate`, `CronDelete`, `CronList`, `DesignSync`, `Edit`, `EnterWorktree`, `ExitWorktree`, `ListAgents`, `NotebookEdit`, `Read`, `ReportFindings`, `ScheduleWakeup`, `SendMessage`, `Skill`, `TaskStop`, `Workflow`, `Write` plus the three `mcp__cowproof-tools__*` MCP tools. A builder must not spawn agents, schedule work, message others, load skills, or make worktrees.
   - **Fix:** Pass `--tools Bash,Read,Edit,Write,Glob,Grep` (the safe subset for builders) and `--disallowedTools Task,Workflow,SendMessage,ScheduleWakeup,CronCreate,Skill,EnterWorktree` as defence in depth. Implemented in `crates/cowproof-run/src/claude.rs` constant `BUILDER_BUILTIN_TOOLS` with doc comment (why each excluded class is excluded), passed in stable argument order, verified in unit tests (`args_contain_tools_flag`, `args_contain_disallowed_tools_flag`, `forbidden_tools_not_in_allowed_list`) and cli test (run.rs line 519).
8. **Linux only: the D24 bridge.** A real `claude` on Linux cannot reach the proxy.

## Step 3 gaps (run)

- The clone is `git clone --no-hardlinks`, a full copy, not the copy-on-write clone the design and README promise (a director ruling, chosen for isolation).
- The macOS profile allows writes by default; a write outside the home and the grants succeeds.
- `cowproof run` has no port block, no disk floor, no builder class slot, no sandbox preflight and no `--unsandboxed`.
- The prefix version is computed and never recorded.
- `legacy-run` remains, against Q-2 (one runner).

## Step 4 gaps (escalate)

- No `cowproof ask`, `ruling` or `check` mirrors for runtimes without MCP.
- Rulings on non-blocking asks (stop, reassign, redirect) are stored and never acted on.
- `watch` reads `exit_code`; `run` writes `exitCode`, so the state column never shows a result.
- Ruling, delivery, rejection, fallback and limit events carry no timestamp; ruling latency cannot be computed.
- `watch --events` never reports a parked ask past the cache lifetime, and `parked()` counts non-blocking asks.

## Step 5 gaps (prove)

- `capsule.json` is not hashed, so `base_commit`, `flaky_checks`, `unsandboxed` and `lane_state` can be edited undetected.
- Gate configuration (`repo_rules`) is read from the director's working tree, not the base commit.
- The protected-paths gate gets an empty list from `cowproof run`, and its defaults are narrower than the design.
- `packets/` and `applied/` are created empty; `checks/` holds placeholder duration, attempts and output hash.
- Parked time, per-segment models and portkit trace totals are not recorded.
- `run_check` does not retry flaky checks; the verifier does.

## portkit integration gaps

- No `pk` binary and no `cowproof pk`; `pk-read` installs from a separate package (D2, 4.5).
- No hooks, lane-private state dir, trace totals or `pk doctor --json` per lane (D5); G2 to G15 open except G1 and part of G10.
- None of the 16 port steps was proven by parity against the Node reference: 5 reimplemented, 9 partial, 2 missing (status taxonomy, question and health readers). No Node adapter (P1), no fake-worker harness (P2).
- No port packets (D7) and no polyglot adapters (D8).
- Licence question open: portkit crates are `MIT OR Apache-2.0`, cowproof crates MIT; `NOTICE` has no portkit entry.

## Live smoke runs (2026-10-10, macOS, real `claude` 2.1.295, Haiku 5.5)

- **smoke-1**: proved in 4 turns, $0.0076. `run_check` called through the cowproof MCP tools; 1-hour cache writes only; the real key in no file under the lane; the proxy's https upstream and header allowlist worked against the live API. Finding: the builder had Claude Code's full built-in tool set (`Task`, `Workflow`, `Cron*`, `ScheduleWakeup`, `SendMessage`, `Skill`, `EnterWorktree`).
- **smoke-2** (after the tool restriction merged): the builder exited 1 with "Input must be provided": `--disallowedTools` takes several values, so as the last flag it swallowed the prompt. The fake-`claude` tests could not catch it. Fixed by passing both lists in the `--flag=value` form, with a unit test that no variadic flag can precede the prompt.
- **smoke-3** (with the fix): proved in 4 turns, $0.0032; the builder's tools are exactly `Bash`, `Edit`, `Glob`, `Grep`, `Read`, `Write` and the three cowproof tools.

Still open under blocker 7: the R15 proof that a project hook and `CLAUDE.md` have no effect, and the same smoke on Linux (needs blocker 8).
