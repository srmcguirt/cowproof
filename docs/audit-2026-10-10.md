5. **Dependency prefetch (D6, D11, D14).** Resolved for Cargo (2026-10-10). Before verify runs, `cowproof run` rebuilds the tree (base, `base.patch`, launch baseline, `lane.patch`), computes `dependency_cache_key` on it and fetches into `<cache root>/deps/<key>/` (`~/.cache/cowproof`, or `$COWPROOF_CACHE_ROOT`): `cargo fetch --locked` under `SandboxPolicy::dependency_fetch` in a private work directory, renamed into place atomically. The fetch holds no key, no control directory and no home, runs no `build.rs`, and gets the network named by `$COWPROOF_FETCH_NETWORK`: `open` (full outbound, the default, because no registry-only filter exists) or `none`. A fetch failure is `infrastructure`, exit 4, naming the fetch (F-1). The capsule records the key and `hit`, `fetched` or `failed` under the seal. `cowproof verify` fetches the capsule's key when its own cache lacks it. Tests (`crates/cowproof-cli/tests/deps.rs`, a real run with the fake claude and a real cargo, no network): proved with outcome `fetched` then `hit` for a second lane; a changed lockfile misses; a failing fetch is exit 4 with no half cache; a check writing into the verifier's registry diverges and is named; a patch to `.cargo/config.toml` is refused by the gate while the fetch still uses the base config; a held-out `cargo build --offline --locked` builds from the mounted git-index registry; `verify` on another cache root fetches and reproduces; unit tests for the atomic install and its race. **Not covered: npm, yarn, pnpm and Bundler** (no fetch adapter; see `docs/backlog.md`).

## Step 3 gaps (run)

- ~~The clone is `git clone --no-hardlinks`, a full copy, not the copy-on-write clone the design and README promise (a director ruling, chosen for isolation).~~ **RESOLVED: COW implemented with cp -c/-reflink/fallback for objects only; clone_method recorded in control/lane.json**
- ~~The macOS profile allows writes by default; a write outside the home and the grants succeeds.~~ **RESOLVED (2026-10-10, lane/macos-write-deny):** `render_macos_profile` writes `(deny file-write* (subpath "/"))` directly after `(allow default)`, then the read-write grants, then one allow for four device files (`/dev/null`, `/dev/zero`, `/dev/tty`, `/dev/dtracehelper`), then the read-only denies, so Seatbelt's last-match-wins order lets every grant beat the global deny and every read-only path inside a read-write grant stay read-only. Everything that is not a file write stays `(allow default)`. The read-only deny is kept: the global deny makes a read-only mount unwritable by itself, but a read-only path nested in a read-write grant needs a later deny to win. Proved three ways: four unit tests on the rendered text (deny directly follows `(allow default)` in all five policies, every write allow follows it, every read-only deny follows every write allow, the device literals are present); a live test that runs a real `/bin/sh` under the real rendered profile with an rw dir and an ro dir nested in it, under `/var/tmp` (a fresh file outside the grants is denied, a file in rw is written, a file in the nested ro is denied, `> /dev/null` works, `git init` and a commit in rw work); and the existing sandboxed suites (`cowproof-run --test live`, `cowproof-cli --test run --test verify --test deps`, all with `COWPROOF_REQUIRE_SANDBOX=1`) pass unchanged, so no further path needed a grant. Mutations caught: no global deny, the global deny moved after the grants, `/dev/null` dropped from the allow, and the read-only deny dropped. **Side effect, found by a live smoke with the real `claude` 2.1.295 and RESOLVED in the same lane:** the runner clears the environment and set no temp directory, so Claude Code's Bash tool failed before running anything (`EPERM: mkdir '/private/tmp/claude-501/...'`: it builds its temp dir as `$CLAUDE_CODE_TMPDIR/claude-<uid>`, else from `$TMPDIR`, else `/tmp`). Now every policy that writes the lane's scratch (builder, `run_check` and the git capture steps, the verifier) sets `TMPDIR` to `<scratch>/tmp`, and the builder also sets `CLAUDE_CODE_TMPDIR` to it. `cowproof run` creates `<lane>/scratch/tmp`, and `verifier_runner` creates `<verify dir>/tmp`; no `/tmp` or `/var/folders` grant. Tests: a unit test on every policy's environment, and a fake-builder run in which the builder runs `mktemp "${TMPDIR:?}/builder.XXXXXX"` and writes to it, a declared check does the same in `run_check` and again in the verifier, the builder's environment names a directory inside the lane for both variables, and the lane is proved. Mutations caught: `TMPDIR` dropped, `CLAUDE_CODE_TMPDIR` dropped, the verifier's `TMPDIR` dropped. **Remaining limit:** Apple's `/usr/bin/mktemp` with no template (and with `-t` or `-d` alone) ignores `TMPDIR` and uses the per-user `/var/folders/.../T` directory from `confstr`, so a bare `mktemp` is still denied inside the sandbox (`mkstemp failed ... Operation not permitted`); `mktemp "$TMPDIR/name.XXXXXX"`, Python's `tempfile`, `std::env::temp_dir` (cargo, rustc) and git honour `TMPDIR` and work. Granting the per-user temp directory would fix it but is shared with every process of the user, so it is not done; the choice is the director's.

Not re-run live in this lane; the Linux container live tests from the D24 work cover the bind layout.

## Step 4 gaps (escalate)

- **Resolved** (lane/cli-mirrors): `cowproof ask`, `cowproof ruling [<id>]` and `cowproof check <id>` forward the same requests as the MCP tools through one shared function (`lane_tools::forward`). Socket from `--socket <path>` or the `COWPROOF_RUNNER_SOCKET` env var (set by the runner in the builder environment). Output is the runner's JSON response (ok field removed). `tests/mirrors.rs` takes the expected request from the MCP surface, not from the CLI's own code: it calls the registered tool from `lane_tools::server` with a literal input written to the tool's schema (and once through the stdio `tools/call` protocol), runs the CLI with the equivalent flags, and compares the two requests the fake runners recorded.
- Rulings on non-blocking asks (stop, reassign, redirect) are stored and never acted on.
- `watch` reads `exit_code`; `run` writes `exitCode`, so the state column never shows a result. **RESOLVED: lane/small-fixes** — `get_lane_state` reads `status`, `exitCode`, and legacy `exit_code`; shows stopped, proved, refuted, incomplete, infrastructure where run.json or verdict.json says so.
- Ruling, delivery, rejection, fallback and limit events carry no timestamp; ruling latency cannot be computed. **RESOLVED: lane/small-fixes** — `Ruled`, `Delivered`, `ResumeFallback`, `LaneEscalationLimit` events now carry `at_ms` with `#[serde(default)]`; set from queue's clock; `watch --events` prints RFC3339 times.
- `watch --events` never reports a parked ask past the cache lifetime, and `parked()` counts non-blocking asks. **RESOLVED: lane/small-fixes** — `parked()` counts only BLOCKING, unruled, undelivered asks; can detect past-cache from at_ms; past-cache event to be emitted when blocking ask's age crosses --cache-ttl.
- **Resolved** (lane/director-serve, 2026-10-10): D4, `cowproof serve --director`. It is the director's MCP server for Claude Code's `.mcp.json` (`claude mcp add cowproof -- cowproof serve --director`), served over stdio by `portkit_mcp` from a registry of four portkit tools: `lanes`, `events`, `rule` and `note`. Each takes an optional `lanes_root`, defaulting through `run::lanes_root` (now defined once in `root.rs`, which the library crate can reach, and re-exported from `run.rs`). No tool waits for a lane: `lanes` and `events` read files and return at once, `events` returns what is there now plus a cursor (per-lane byte offsets; a half-written last line is held back, a made-up cursor is an error), and `rule` and `note` are one bounded request on `control/director.sock` (10 s limit).
  - **One code path.** `director_tools::send_rule` and `send_note` build and send the request; `cowproof rule`, `cowproof note` and the two tools call them, and `main.rs` has no socket code for either. `lanes` and `events` use `watch::lane_snapshots` and `watch::read_events`, the data the `watch` table and `watch --events` now print from. `cowproof --version` prints `cowproof <workspace version>`, and `BRIDGE_READY_TIMEOUT` is 30 s (first launch of a fresh binary took 10.4 s on macOS; the backlog entry is resolved).
  - **Proof** (`tests/director_tools.rs`, `tests/cli.rs`). A fake `director.sock` records requests. For each ruling kind `RuleArgs` supports (answer, redirect, reassign, reassign with a model, stop) and for note, the real `cowproof rule` / `cowproof note` binary sends once and the tool taken by name from `director_tools::server`'s registry sends once; the recorded requests must be equal as JSON, and equal to the expected literal. `lanes` for a two-lane fixture matches the state, parked cell and note count `cowproof watch` prints. `events` with a cursor returns only newer events, holds back a half-written line, and agrees with `watch --events`. One stdio round through the real `cowproof serve --director` initializes, lists exactly the four tools and lands a `rule` on the fake socket. `--version` is compared with the workspace version. Hand mutations that each fail a test: the `rule` tool always sending `answer`, `events` ignoring its cursor, `version` removed from the clap command, `note` on the CLI diverging from the tool; moving the shared socket path to `runner.sock` fails the rule, note and stdio tests, because both surfaces change together.
  - **Open.** `lanes` returns a parked escalation's id and age, and `events` returns runner-owned summaries (ids, flags, sizes); neither returns the ask itself (kind, question, tried, options, recommend), which is only in `control/escalations.jsonl`. A listing of open escalations that returns the ask, in a fenced, length-capped block per the trust-boundaries rule in the design, does not exist. The first `events` call has no size limit. The plugin has no `.mcp.json` yet, so its skills still use the shell commands. `watch --json` is not built; `lanes` is its data.

## Step 5 gaps (prove)

- Done (2026-10-10): `capsule.json` is sealed. `Capsule::write` hashes its raw bytes as written into `capsule.sha256`; `read` checks the seal before it parses. There is no self-hash inside the file and no re-serialization. Editing `lane_state`, or `unsandboxed`, or only reformatting the file makes `read` fail. The seal catches edits and damage, not a forger who rewrites the seal too (signing comes later).
- Done (2026-10-10): the protected list loads from the base commit (`git show <base>:lanes.config.json`), through the one parser in `cowproof_core::repo_rules_from_config`. An uncommitted protected rule has no effect, a committed one does, and a committed rule edited away in the working tree still applies.
- The protected-paths gate gets an empty list from `cowproof run`, and its defaults are narrower than the design.
- `packets/` holds only the held-out checks, when there are any (no packet versions), and `applied/` is created empty; `checks/` holds placeholder duration, attempts and output hash.
- Parked time, per-segment models and portkit trace totals are not recorded.
- `run_check` does not retry flaky checks; the verifier does.
