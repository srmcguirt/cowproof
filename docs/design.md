## Problem Statement

Running many AI coding workers in parallel on one project is now easy. Trusting what they hand back is not. Cheap workers game their checks: they delete assertions and keep the test names, write always-true security policies, swallow their own exceptions, or report deferred work as done. A director agent that reads every diff becomes the bottleneck, and one that doesn't read them lets that work land.

The founder has run hundreds of lanes on the Everydom platform with a home-grown runner (`scripts/lanes/` in that repo, plus six Rust crates in the private `Everydom/lanes`) and three director skills (`lane-dispatch`, `lane-handback`, `lane-escalate`). It works, but it is Everydom-specific, needs Node and Rust, and its escalation path is a one-way question file. cowproof rebuilds it as an MIT tool that the founder's own projects and outside users can run.

Target shape, in the founder's words: "I'm imagining having opus running the build direction with haiku builder. Haiku escalates the problem as a message back to the director, for direction. Director escalates to another agent or directs with solution/answer to question."

## What Makes This Cool

- **The work comes back as a proof, not a claim.** Each lane returns a proof capsule: base revision, patch hash, checks re-run by a verifier the builder never controlled, held-out check results, gate results and the escalation log. Any machine (CI, a reviewer, the founder's next project) can replay it.
- **Cheap builders, expensive judgment, spent only where it matters.** Haiku does the token-heavy work. Opus spends tokens on rulings and on the exceptions the gates surface, never on routine diffs.
- **The name does the explaining.** Every lane runs on a copy-on-write (COW) clone, the work must come back proven, and the real tree is cow-proof: builders graze in their own clones and cannot trample it.

## Constraints

- MIT, public on `srmcguirt/cowproof` after the founder reads the polished design. Fresh git history: the `Everydom/lanes` history holds a host inventory, private paths and project packets.
- One installable binary for outside users. No Node requirement in the first public release.
- The runner never writes to the real tree. Every applied change goes through the director.
- Every role (director, builder, ladder, challenger) is configuration. Codex and OpenRouter builders keep working.
- Two auth modes for outside users (founder decision, 2026-10-09): Anthropic API key and Claude subscription. cowproof never runs a login flow, stores a token or pools a subscription. See Open Question 1.
- Cost figures from Claude Code are client-side estimates (`total_cost_usd`, per the headless docs); cowproof labels them as estimates everywhere.
- macOS (sandbox-exec, APFS clonefile) and Linux (bubblewrap, reflink) from the first release; Windows through WSL only.
- Everydom keeps its current runner until cowproof has run real waves.

## Premises

1. **The director's attention is the bottleneck, not compute.** Mechanical proof gates carry most review; the director reads gate reports, exceptions and escalations, not diffs. (agreed)
2. **Haiku is the default builder; escalation is the safety net.** Revised by the founder, who rejected a model bake-off before launch: "Escalation is the net." Escalation therefore has to be cheap and early. A builder must escalate after a bounded number of failed attempts on the same check or past a share of its cost cap, rather than thrash. Escalation and reassign rates are measured in production. (agreed as revised)
3. **Outside users need one installable binary.** The runner's Rust port, proven with portkit parity fixtures, moves into the first release instead of a late phase. (agreed)
4. **The novel part is escalation plus proof, not parallel lanes.** COW worktrees and parallel agents are common (`lukeed/lane`, `simgit`, `git-cow`, Vibe Kanban, Conductor, Claude Code subagents). The escalation protocol and the proof gates ship first and best; remote hosts and plan files follow. (agreed)

## Approaches Considered

Move the Node runner, crates and skills over as they are. Ruled out: two runtimes for outside users and no differentiator at launch (breaks premises 3 and 4).

### Approach B: Escalation-and-proof slice first, then fold the runner in

## Recommended Approach

**Approach B.** Build a Rust `cowproof` binary that runs one loop end to end, then port the existing runner's features into it, each proven against the Node original with portkit parity fixtures.

### Roles

| Role | Default | Job |
| --- | --- | --- |
| Director | Opus, in the user's Claude Code session | Writes packets, rules on escalations, judges exceptions, applies, gates, commits |
| Builder | Haiku 4.5 through headless Claude Code | Implements one packet inside its lane |
| Ladder | Sonnet, then Opus | Takes over a lane the director reassigns |
| Challenger | a different model family where available | Attacks a design ruling or a packet's checks |

Codex CLI and OpenRouter (opencode) builders remain supported.

### Lifecycle

```
packet -> lint -> preflight -> dispatch -> run <-> escalate -> handback -> verify -> gates -> capsule -> director -> apply, gate, commit
```

- **Packet**: a task file with a JSON header: id, `owns` globs, command allowlist, role, model, timeout, cost cap, resource class, `appendOnly` guards, protected paths, and held-out checks stored outside the builder's clone. Reuses `lanes-core` parsing.
- **Lint**: refuses packets with masked pipe statuses, missing check paths, secret references or reservation clashes. Reuses `lanes-lint`.
- **Preflight**: a cheap adversarial pass tries to satisfy the packet's visible checks by cheating (stubbing, deleting assertions, hard-coding outputs). If a cheat passes, the checks go back to the director. Idea from SpecGuard (arXiv 2610.09159) and GraderGuard. Not in the first slice.
- **Dispatch**: COW clone (APFS clonefile, reflink, copy fallback), OS sandbox, lane-private HOME and Claude config directory, port block, scratch directory, machine-wide class slots, disk floor. Ported from `run-lane.mjs`.
- **Run and escalate**: see the escalation protocol.
- **Handback**: in-scope patch, outside-ownership patch (kept, never applied), handoff, `summary.json`, `escalations.jsonl`, portkit trace.
- **Verify**: the verifier applies the patch to a fresh clone of the base revision, outside any builder process, and runs the visible checks and the held-out checks. The builder's own reported results are informational only.
- **Gates**: mechanical checks over the patch and the verifier's results (see Proof gates).
- **Capsule**: everything above sealed into one replayable record.
- **Director**: reads the gate report, open escalations, the handoff's limits and questions, and greps the patch only where a gate points.

### Escalation protocol

The builder gets one tool, served by cowproof as an MCP server inside the lane and mirrored as `cowproof ask` for runtimes without MCP:

```json
{
  "kind": "blocker | design | scope | environment",
  "question": "one paragraph",
  "tried": ["what was attempted and what happened"],
  "options": [{ "id": "a", "summary": "...", "cost": "..." }],
  "recommend": "a",
  "blocking": true
}
```

- `blocking: false`: the builder keeps working on unblocked parts and checks for a ruling between steps.
- `blocking: true`: the builder parks. Tokens stop; parked time is paused against the lane timeout.
- **Escalate early.** The runner forces an escalation when the builder fails the same check twice or spends 40% of its cost cap without a passing check (both configurable). This is what keeps Haiku's misses cheap.
- Limits per lane: 3 escalations and 30 minutes parked by default. Beyond either, the lane ends as `escalation-limit` with its work kept.

Escalations land in a file-backed queue in the lane directory, so they survive restarts and work for every runtime. The director follows one stream, `cowproof watch --events`, which a Claude Code Monitor can tail, and rules with `cowproof rule <lane> <verdict>`:

| Verdict | Effect |
| --- | --- |
| `answer` | A short ruling is written into the running lane; the builder resumes |
| `redirect` | A revised packet replaces the current one; the lane continues on its clone |
| `reassign` | The lane moves to the next model on the ladder (or a named one), carrying its clone, patch so far, the question and a compact summary of what was tried |
| `stop` | The lane ends; its work is kept for inspection |

For a design question the director cannot settle alone, the existing `lane-escalate` flow applies: a stronger model recommends, a challenger attacks the recommendation, the director adopts. Every escalation and verdict is logged and summarized in the handoff, so the capsule shows which decisions were the builder's and which were the director's.

### Proof gates

| Gate | Catches | Source |
| --- | --- | --- |
| Ownership | changes outside `owns` | exists |
| Append-only | deleted assertions, emptied test files | exists |
| Protected paths | edits to tests, fixtures or policies the packet must not touch | new |
| Verifier re-run | checks the builder claimed but that fail when run independently | new |
| Held-out checks | work that satisfies only the visible checks (idea: EvilGenie, SpecBench) | new |
| Flaw rules | known gaming patterns: swallowed exceptions in assertions, always-true policies, test-only code in production paths, secrets in URLs | exists as `lanes-report` `flaws.toml`; split into a generic pack and project packs |
| Claimed vs. run | handoff checks the verifier never saw | exists in part |

A gate verdict is a triage signal; the director still rules. Each new flaw found at handback becomes a rule.

### Proof capsule

`capsule.json` in the lane directory, content-addressed:

- base revision and tree hash; packet hash; patch SHA-256
- verifier check results: command, exit code, duration, output hash
- held-out check results; gate results
- escalation log hash and verdict summary
- builder and director models, auth mode, estimated cost and tokens, portkit trace totals

`cowproof verify <capsule>` replays it on any machine: clean clone at the base revision, apply the patch, re-run the checks, compare. Signing comes later.

```

```

It reads lane files only; there is no daemon. Idle time past a class threshold is flagged as a stall. `--json` and `--events` give the director agent a compact feed, so it never needs raw logs.

### portkit integration

portkit (`pk`, the founder's Rust CLI) ports Python scripts to Rust CLI tools with a parity harness and measures agent tool usage through hooks. It has two jobs here:

1. **Porting harness.** Each piece of `run-lane.mjs` (header parsing, status classes, ownership split, append-only check, sandbox profile generation, clone strategy) gets wrapped in portkit's stdin/stdout JSON contract. `pk port capture` records what the Node runner does, and the Rust replacement must pass `pk port replay` before the Node path is deleted. Deliberate differences become scoped `accepted` entries with written reasons. The same mechanism gives users a **port packet**: a builder ports a script to a Rust CLI, and parity fixtures are its proof.
2. **Usage monitor.** Each Claude builder lane gets portkit's hooks (`post-tool-use`, `user-prompt-submit`, `session-end`) in its private config, a lane-local `PORTKIT_STATE_DIR`, the `pk-read` and symbol tools to cut re-reads, and `pk doctor` as a preflight; otherwise the lane reports `untraced`. Trace totals roll into the summary, the capsule and the watch view.

Efficiency metrics, per lane and per wave: estimated cost per **accepted** patch; escalations and reassigns per lane by model; director minutes per lane; tokens per changed line; context bytes delivered and saved; re-read rate.

cowproof calls the `pk` binary when present. A crate dependency can follow once both stabilize.

### Auth and cost

Verified against Claude Code documentation on 2026-10-09:

- **API key** (`auth = "api-key"`): `ANTHROPIC_API_KEY` or `apiKeyHelper`, always used in `-p` mode. Builders run with `--bare`, which skips the user's hooks, skills, plugins and MCP servers; cowproof supplies its own with `--settings` and `--mcp-config`. Recommended mode for outside users and teams.
- **Subscription** (`auth = "subscription"`): the user runs `claude setup-token` (documented for "CI pipelines, scripts") and exports `CLAUDE_CODE_OAUTH_TOKEN`. `--bare` does not read that token, so subscription builders are isolated with a lane-private `CLAUDE_CONFIG_DIR` instead.
- The runner caps concurrent builders per auth mode and backs off on rate-limit errors; the docs don't state concurrency limits for subscriptions.

## Open Questions

1. **Subscription mode in public docs (founder; terms).** The Agent SDK overview says: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products." cowproof offers neither; it runs each user's own `claude` binary with their own credential. Whether a published tool may document that mode is a judgment on Anthropic's terms, possibly worth asking Anthropic. Until settled, the README presents API keys as the supported path.
2. **Who writes held-out checks.** They cost director attention per packet. Options: the director writes them at dispatch; a separate challenger lane drafts them from the packet; or they are optional and the gate reports their absence. Decide after the slice shows what they cost.
3. **Escalate-early defaults.** Two same-check failures and 40% of the cost cap are starting guesses; tune from the first real wave's escalation data.
4. **Everydom adoption.** When Everydom switches runners is a separate decision after real waves.

## Success Criteria

- **Slice works:** a Haiku builder completes a synthetic packet, raises at least one escalation the director answers through `cowproof rule`, and produces a capsule that `cowproof verify` replays green on a second machine.
- **Gates catch cheating without a diff read:** an adversarial packet (a builder told to delete an assertion and hard-code an output) fails the gates, and the director learns it from the gate report alone.
- **One install:** `cargo install cowproof` and the release binaries run the full loop on macOS arm64 and Linux x86_64 with no Node.
- **Escalation stays cheap:** in the first real wave, escalated lanes cost less in total than if every lane had started on Sonnet. Reported from the capsules, not asserted.
- **Real use:** one Everydom wave runs on cowproof with estimated cost per accepted patch reported.

## Distribution Plan

- GitHub Releases with prebuilt binaries for macOS (arm64, x86_64) and Linux (x86_64, arm64), built by a release workflow on tags; `cargo install cowproof` from crates.io. A Homebrew tap follows the first release.
- Skills as a Claude Code plugin from the repository's marketplace manifest, plus the `.agents/skills` copy.
- CI: GitHub Actions runs the test suite, the portkit parity replay against captured Node fixtures until the Node runner is deleted, and a capsule replay of a committed sample lane.
